# Merchant Globe MVP 0.4

실제 세계 도시를 배경으로 한 무역 경제 시뮬레이션의 초기 실행 버전입니다. 0.4의 핵심은 **같은 5개 도시와 12개 상품 안에서도 거래 판단이 더 다양하게 바뀌도록 만드는 것**입니다.

## 현재 구현된 기능

- 도시 5개: 서울, 부산, 후쿠오카, 오사카, 상하이
- 상품 12개
- 도시별 장기 가격 특성
- 도시별 생산 / 소비 성향
- 재고·수요 기반 동적 가격
- 거래량에 따른 시장 충격과 매수/매도 스프레드
- 시장 재고를 초과하는 매입 제한
- 시간 경과에 따른 재고·수요 회복
- 축제 / 유행 / 증산 / 공급 차질 시장 이벤트
- 항로 혼잡 / 순풍 이벤트
- 상품별 특성: 안정형 / 변동형 / 고변동 / 중량품 / 신선품
- 수산물 신선도 하락
- 중량품의 추가 화물칸 사용
- 평균 매입가, 보유 손익, 화물 적재량
- 도시 이동 시간 및 운송비
- 화물칸 확장
- 30일 플레이 및 결과 통계
- 시장 정보망 및 오래된 정보(stale intel)
- 시장 사건의 정보 정확도 제한
- 브라우저 로컬 자동저장 / 이어하기
- RandomBot / GreedyBot headless 자동 플레이
- 상품·항로 집중도 밸런스 리포트
- 경제 엔진 / 저장 복원 / 시뮬레이션 자동 테스트

## 0.4 경제 다양성

### 도시 생산 / 소비

도시별 가격 배율뿐 아니라 생산과 소비 성향이 실제 시장 재고·수요에 반영됩니다.

예시:

- 서울: 인삼·종이 생산 강점, 향신료 소비 강점
- 부산: 수산물 생산 강점
- 후쿠오카: 차·목재 생산, 인삼 소비
- 오사카: 철·도자기·구리 생산, 인삼 소비
- 상하이: 차·비단·면직물 생산, 목재 소비

생산 특성이 높은 상품은 평시 재고 목표가 크고 부족해졌을 때 회복도 빠릅니다. 소비 특성이 높은 상품은 평시 수요가 높고 수요가 시장 특성 쪽으로 돌아가는 힘도 강합니다. 0.4 밸런스 조정에서는 가격 배율과 생산/소비 계수가 같은 방향으로 과도하게 중복 증폭되지 않도록 생산·소비 정체성의 목표치 영향은 약 55%로 완화했습니다.

### 상품 특성

| 특성 | 효과 |
|---|---|
| 안정형 | 상대적으로 낮은 가격 변동과 이벤트 민감도 |
| 변동형 / 고변동 | 이벤트에 더 크게 반응 |
| 중량품 | 상품 1개당 화물칸 2칸 사용 |
| 신선품 | 이동으로 날짜가 지나면 신선도가 하락하고 실제 판매 가치도 감소 |

현재 신선품은 수산물이며, 신선도는 하루마다 약 7%씩 감소하되 최소 가치가 보장됩니다.

### 시장 이벤트

0.3의 단순 수요/공급 이벤트를 다음처럼 확장했습니다.

- 축제: 특정 상품 수요 급증
- 유행: 일정 기간 소비 증가
- 증산: 재고 증가와 공급 확대
- 공급 차질: 재고 감소와 공급 목표 하락

상품마다 이벤트 민감도가 달라 같은 사건도 가격 압력이 다르게 나타납니다.

### 항로 이벤트

항로도 항상 같은 비용과 시간이 보장되지 않습니다.

- 항로 혼잡: 운송비 +25%, 이동 +1일
- 순풍: 운송비 -12%, 이동 시간 최대 1일 단축

이 때문에 가장 큰 가격 차이가 항상 최고의 거래가 되지 않습니다.

## 저장 / 이어하기

브라우저 `localStorage`에 단일 저장 슬롯을 사용합니다.

- 매입 / 판매 / 이동 / 화물칸 확장 / 정보망 확장 후 자동저장
- 상단 `저장` 버튼으로 수동 저장 가능
- 새로고침하거나 다시 접속하면 저장 상태를 자동으로 복원
- `저장 삭제`로 로컬 저장 슬롯 삭제
- `새 게임`은 기존 저장을 덮어쓰기 전에 확인

저장 데이터는 현재 상태를 단순 복사하는 대신 **초기 난수 시드 + 성공한 플레이 행동 기록**을 저장합니다. 불러올 때 동일한 행동을 재생하므로 현재 시장뿐 아니라 이후 발생할 경제 변동과 이벤트의 난수 흐름도 이어집니다.

저장 형식은 버전 검사를 하며, 현재는 같은 `0.4.0` 저장만 불러옵니다.

## 0.4 인삼 밸런스 조정

초기 봇 시뮬레이션에서 인삼이 대부분의 seed에서 최고 수익 상품이 되어 지역 정체성은 유지하되 가격 극단을 완화했습니다.

- 서울 인삼 가격 배율: `0.68 → 0.80`
- 서울 인삼 생산 계수: `1.40 → 1.25`
- 부산 인삼 가격 배율: `0.88 → 0.94`
- 후쿠오카 인삼 가격 배율: `1.34 → 1.22`
- 후쿠오카 인삼 소비 계수: `1.38 → 1.22`
- 오사카 인삼 가격 배율: `1.38 → 1.22`
- 오사카 인삼 소비 계수: `1.42 → 1.28`
- 상하이 인삼 가격 배율: `1.27 → 1.18`

서울은 여전히 인삼 생산지이고 일본 도시는 여전히 인삼 소비가 강하지만, 인삼 하나가 모든 다른 상품의 기회비용을 압도하지 않게 하는 것이 목적입니다.

### 비단 추가 조정

인삼 조정 후 상하이→후쿠오카 비단이 새 고정 정답 후보로 올라와 다음 값도 완화했습니다.

- 상하이 비단 가격 배율: `0.69 → 0.78`
- 상하이 비단 생산 계수: `1.45 → 1.30`
- 후쿠오카 비단 가격 배율: `1.16 → 1.10`

상하이는 여전히 비단 공급지이지만 한 상품/한 항로가 다른 선택을 압도하지 않도록 조정했습니다.

## Windows 프로토타입 환경

현재 프로토타입의 기준 개발/수동 테스트 환경은 **Windows + PowerShell**입니다.

권장 버전:

- Node.js 22
- Python 3.12

프로젝트 루트에서:

```powershell
cd prototype\web-v0
npm run dev
```

`npm run dev`는 내부적으로 `python server.py`를 실행합니다.

기본 바인딩 주소는 `127.0.0.1`입니다. 같은 네트워크의 다른 장치에서도 접속할 수 있게 하려면:

```powershell
npm run dev -- --host 0.0.0.0
```

브라우저:

```text
http://127.0.0.1:8000
```

## 봇 시뮬레이션

UI 없이 실제 `Game` 코어를 직접 실행하는 headless 시뮬레이터입니다. 봇에게는 플레이어가 실제로 볼 수 있는 현재 도시 정보와 `remoteIntel()` 기반 원격 정보만 제공됩니다. GreedyBot의 이동은 실제 상품을 싣고 가는 `trade`와 정보 갱신을 위한 `explore/reposition`으로 구분하며, 고정 항로 밸런스 경고는 `trade` 이동만 집계합니다.

기본 실행은 RandomBot과 GreedyBot을 각각 100판씩 실행합니다.

```bash
npm run simulate
```

빠른 확인:

```bash
npm run simulate:quick
```

GreedyBot 1,000판 밸런스 실행:

```powershell
npm run simulate:balance
```

동일한 실행을 옵션으로 직접 지정할 수도 있습니다.

```powershell
npm run simulate -- --runs 1000 --bot greedy
```

상세 결과를 JSON 파일로 저장:

```bash
npm run simulate -- --runs 1000 --bot all --output simulation/report.json
```

지원 옵션:

- `--runs N`: 봇당 실행 횟수
- `--bot random|greedy|all`: 실행할 봇
- `--seed PREFIX`: 재현 가능한 시드 prefix
- `--output FILE`: 상세 JSON 리포트 저장
- `--quiet`: 콘솔 요약 숨김

리포트에는 평균/중앙 최종 자산, P10/P90, 실현손익, 운송비, 상품별 수익, seed별 최고 수익 상품 빈도, 단방향 항로 이용률, 왕복 항로 이용률, 완주율이 포함됩니다. 특정 상품의 양의 실현손익 비중이 35% 이상, 한 상품이 seed의 50% 이상에서 최고 수익, 단방향 항로가 30% 이상, 왕복 항로가 35% 이상이면 밸런스 경고를 표시합니다.

별도 npm 의존성 설치는 필요하지 않습니다.

GitHub Actions도 Windows GitHub-hosted runner를 기본 검증 환경으로 사용합니다. PR에서는 GreedyBot 100판 밸런스 샘플도 실행합니다. Linux 검증은 Actions의 수동 실행에서 `runner: linux`, 로컬 Windows self-hosted 검증은 `runner: local`로 선택할 수 있습니다.
