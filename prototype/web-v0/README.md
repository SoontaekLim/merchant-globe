# Merchant Globe MVP 0.6.0

실제 세계 도시를 배경으로 한 무역 경제 시뮬레이션입니다. **0.6 기본 화면은 종료가 없는 실시간 무역 프로토타입**이며, 기존 0.5.4의 30일 플레이테스트는 별도 `classic.html`로 유지합니다. 양쪽 모두 0.4의 도시 5개·상품 12개 경제 규칙을 재사용합니다.

## 0.6 실시간 경제·운송 (새 기본 화면)

브라우저에서 `http://127.0.0.1:8000`에 접속하면 **0.6 실시간 모드**가 실행됩니다. 기존 30일 테스트는 `http://127.0.0.1:8000/classic.html`에서 사용할 수 있습니다.

- **거래와 무관한 경제 갱신:** 거래나 도시 이동을 하지 않아도 경제 시간이 흐르고 도시별 시세·시장 재고·수요·이벤트와 수산물 신선도가 갱신됩니다. 새 게임의 시연 속도는 기본 **현실 60초 = 게임 1일**, 테스트 가속 **현실 10초 = 게임 1일**입니다.
- **진행 기간 무제한:** 실시간 게임은 30일 종료 없이 계속할 수 있습니다. 30일 종료 시스템은 기존 클래식 테스트에서만 사용합니다.
- **지연 운송:** 출발 시 항로 이벤트가 반영된 실제 운송비를 **한 번만 차감**하고, 해당 경로의 게임 일수에 비례해 현실 시간이 흐른 뒤 도착합니다. 운송 중에는 매입·판매·업그레이드·다른 항로 출발을 할 수 없으며, 경제와 신선도 변화는 계속됩니다.
- **실시간 UX:** 기존 상품별 가격·기준가 대비·평균 매입·보유 손익, 수량 단축, **이동비 확보 최대 매입**, 화물칸 직접 판매, 시세 정보망을 새 모드에서도 제공합니다.
- **오프라인 복구:** 브라우저를 닫아도 다음 접속 시 실제 경과 시간을 반영하고, 운송 종료 시각을 지났다면 도착 처리를 합니다. 초기 시드, 시작 시각, 각 행동의 시각·수량 및 목적지를 재생해 복원하므로 미래 시장 난수 흐름까지 동일합니다.
- **별도 저장:** 실시간 모드의 로컬 저장 키는 `merchant-globe.realtime.save.v1`이며, 기존 클래식의 `merchant-globe.mvp.save.v1`을 수정하거나 삭제하지 않습니다. 새 게임의 속도 비율은 그 세션의 저장에 고정됩니다.
- **실시간 JSON:** `기록 JSON`으로 행동·시간 데이터와 플레이어의 공개 상태·누적 거래 통계를 내보낼 수 있습니다. 원격 도시의 숨겨진 시장 내부 상태는 포함하지 않습니다.

**현재 제한:** 이것은 **로컬 단일 플레이어용 서버 비권위 프로토타입**입니다. 브라우저·운영체제 시간 조작을 신뢰할 수 없으므로 경쟁용 보안/온라인 경제는 별도 서버 시간이 필요합니다. 매우 긴 오프라인 복구(한 번에 100,000 경제일 초과)는 안전장치가 중단합니다. 무제한 진행은 *게임 종료일이 없다는 뜻*이지 영구적 단일 파일 복원의 무한 성능 보장을 뜻하지는 않습니다. 긴 플레이의 저장 성능을 위해 향후 체크포인트가 필요합니다.

경제 갱신은 **하루 간격의 이산 갱신**이며, 매 초 모든 상품을 갱신하는 방식은 아닙니다. 운송 대기 표시와 도착 시각은 초 단위로 표시됩니다. 현재 시간 배율과 거래 비용·상품 밸런스는 검증용 값입니다.

### 직접 확인할 순서

1. 실시간 기본 화면에서 5개 상품을 매입한 뒤, 거래 없이 시계를 지켜보며 Day와 시장 가격이 바뀌는지 확인합니다.
2. 이동비 확보 최대 매입으로 예정 도시 항로비를 남긴 뒤 **운송 시작**을 누릅니다. 도착 전에는 거래 버튼이 잠기고 도착 후 해당 도시에서 판매됩니다.
3. 항해 중 브라우저 탭을 닫고 운송 시간 이후 다시 접속합니다. 해당 도시로 도착해 있고 자산·화물·시장 시세가 복원되는지 확인합니다.
4. 화물칸에서 선택 판매와 전량 판매를 실행해 손익과 현금을 확인합니다.
5. 30일 기존 봇 밸런스 검증은 `classic.html`에서 계속 가능합니다.

## 0.5.4 화물칸에서 바로 판매

시장 상품 카드를 다시 찾지 않고, 우측 **화물칸** 패널에서 가지고 있는 상품을 곧바로 현재 도시 시세로 판매할 수 있습니다.

- 보유 상품마다 **독립된 판매 수량 입력**과 `선택 N개 판매` / `전량 N개 판매` 버튼을 제공합니다. 시장 화면 위쪽 수량 선택을 바꿀 필요가 없습니다.
- 각각의 버튼 아래에 **실제 대량 체결가 기반 예상 판매대금, 실현손익, 판매 후 현금, 이동 예정 도시로 이동했을 때 남는 현금**을 표시합니다.
- 전량 판매 시 상품이 화물칸에서 사라지고, 시장 재고/현금/화물 적재량이 즉시 갱신됩니다.
- 화물칸 판매는 기존 시장 판매와 **동일한 `Game.sell()`·자동저장·행동 재생 경로**를 사용합니다.
- JSON 플레이 기록의 `tradeControls` 항목에서 `surface: "cargo"`로 구분되며 `tradeControlSummary.surfaceCounts`에 시장/화물칸 거래 횟수가 들어갑니다. 기존 기록의 위치가 비어 있을 때는 당시 유일한 거래 UI였던 `market`으로 취급합니다.
- 게임 종료 시 판매 버튼은 비활성화됩니다. 경제 규칙이나 저장 포맷은 변경하지 않습니다.

**주의:** 화물칸 판매는 현재 머무는 도시에서 체결됩니다. 다른 도시의 예상 판매가격은 보장하지 않습니다. 이동비는 현재 선택한 예정 도시를 기준으로 안내합니다.

## 0.5.3 시장 화면과 이동비 예산 개선

플레이테스트에서 가로 스크롤을 해야 **기준가 대비 변동률, 평균 매입가, 보유 손익**을 볼 수 있었고, 대량 매입·전량 판매 후 다음 도시 운송비를 감당할 수 있는지 계산하기 어려웠습니다.

- 기존 9열 가로 스크롤 시장 표 대신 **상품별 반응형 카드**를 사용합니다. 카드 상단에 현재 시세·도시 기준가 대비 %, 아래에 재고·수요·보유 수량·평균 매입가·보유 손익이 항상 표시됩니다.
- 시장 상단의 **이동 예정 도시**에서 운송비 계산에 사용할 목적지를 고릅니다. 기본값은 현재 가장 저렴한 항로이며, 목적지 선택은 자동 이동을 뜻하지 않습니다.
- 선택 수량 매입/판매의 예상 체결금액과 **거래 후 현금·예정 도시로 이동한 뒤의 현금(또는 부족액)**을 함께 표시합니다.
- 최대 매입·전량 판매도 각 버튼 아래에 **총 금액과 거래 후/이동 후 잔액**을 별도로 보여줍니다.
- 기본적으로 **최대 매입 시 이동비 확보**가 켜져 있어, 선택 도시로 가는 현재 운송비를 남기는 수량만 매입합니다. 끄면 기존처럼 보유 현금 전체 기준으로 최대 매입합니다.
- 이동비 확보 최대 매입은 `reserve_max_buy`로 거래 버튼 사용 로그에 구분해 저장합니다.
- 매입 예측은 실제 체결가의 대량 가격 충격, 시장 재고, 화물칸, 현금과 선택 항로의 혼잡·순풍 비용을 반영합니다. 경제·이동 규칙 자체는 변경하지 않습니다.

**유의:** 이동 예정 도시는 계산에만 쓰이며 실제 이동은 여전히 오른쪽 항로 버튼으로 실행합니다. 운송비는 현재 시점 기준이므로 이후 항로 이벤트·시간 경과에 따라 바뀔 수 있습니다. 화물 가격 변화와 도착 도시 판매 수익을 보장하지 않습니다.

## 0.5.2 플레이테스트 후속 개선

두 번째 플레이테스트에서 5개 매입을 연속 실행한 사례와 업그레이드 비용이 자산 변화에 미치는 영향을 확인해 다음 기능을 추가했습니다.

- 거래 수량 빠른 선택을 **1개 / 5개 / 10개**로 확대. 직접 입력도 계속 지원합니다.
- 성공한 거래마다 `preset_1`, `preset_5`, `preset_10`, `custom`, `max_buy`, `sell_all` 중 실제 사용 방식을 기록합니다.
- 기록에는 거래 행동 인덱스, 상품, 방향, 수량, 현재 도시와 시각이 포함되며, 게임 규칙과 가격에는 영향을 주지 않습니다.
- `tradeControls` 및 `tradeControlSummary`는 플레이 기록 JSON에 추가됩니다. 기존 저장에서 만들어진 거래는 사용 버튼을 알 수 없으므로 `untrackedTrades`로 분리합니다(임의 추정하지 않음).
- 거래 버튼 기록은 브라우저 로컬의 별도 슬롯에 최대 2,000건까지 보관하고 게임 재시작/저장 삭제 시 초기화합니다. **기존 0.4 저장 포맷을 변경하지 않습니다.**
- 리포트의 `investmentCosts`에서 화물칸·정보망 투자비를 별도로 표시하고, 판매 실현손익 → 운송비 차감 → 성장 투자비 차감 순서의 결과를 확인할 수 있습니다.
- 미판매 화물의 평가금액이 최종 자산에 포함되므로 **투자비 차감 후 실현손익과 자산 증감이 일치하지 않을 수 있습니다.**

실시간 경제/무제한 운영은 후속 개발 단계이며, 이번 변경은 기존 턴 기반 테스트 환경에서 거래 입력 및 관측만 개선합니다.

## 0.5.1 거래 UX 개선

0.5 플레이테스트에서 여러 상품을 1개씩 반복 매입·판매한 행동이 발견되어, **기존 경제 규칙은 변경하지 않고** 거래 조작만 개선했습니다.

- 시장 표 위에서 `1개` / `5개` / `10개` 수량을 빠르게 선택하거나, 수량을 직접 입력할 수 있습니다.
- 상품마다 `매입 N개`, `판매 N개` 버튼이 선택 수량을 적용합니다.
- `최대 N개`는 **현금·화물칸·시장 재고·대량 체결 가격 상승**을 모두 계산해 가능한 만큼 한 번에 매입합니다. 운송비는 자동으로 유보하지 않으므로 다음 도시 이동에 필요한 현금을 남길지 판단해야 합니다.
- `전량 N개`는 보유한 해당 상품을 한 번에 판매합니다.
- 거래 전에 실제 시장 충격과 매수·매도 스프레드를 반영한 예상 체결 총액, 평균 단가 및 판매 실현손익을 표시합니다.
- 수량이 부족하거나 돈·화물칸이 모자란 경우 해당 거래 버튼을 비활성화하고 이유를 안내합니다.
- 성공한 대량 거래도 `qty`를 포함하는 기존 0.4 저장·복원 형식을 그대로 사용합니다.

예상 판매 실현손익은 현재 도시에서의 보유 상품 평균 매입가 대비 수치로 **운송비를 포함하지 않습니다.** 실시간 운송/지속형 경제는 후속 단계입니다.

## 0.5 플레이테스트 로그 및 종료 리포트

아래 내용은 **기존 30일 클래식 테스트의 기록 기능**입니다. 게임의 성공한 행동 기록을 재생해 구조화된 플레이 로그를 생성합니다. 별도 서버나 계정이 필요하지 않습니다. 거래 버튼을 실제로 어떻게 조작했는지는 별도 계측 기록으로 보관합니다.

- 매입/판매: 도시, 상품, 수량, 체결단가, 금액, 판매 실현손익
- 이동: 출발/도착 도시, 경과 일수, 운송비, 도시 방문 횟수, 방향별/왕복 항로 이용
- 성장: 화물칸·정보망 업그레이드와 지출
- 시장 사건: **플레이어에게 실제로 공개된 시장 소문 및 항로 공지**만 관측 시점에 기록
- 정보 조회: 플레이어가 원격 시장 탭을 열었을 때 조회 도시, 정보망 수준, 조회 시간, 화면에 공개된 시세만 별도 저장
- 자산: 행동 후 현금·자산, 날짜별 마지막 관측 자산
- 30일 종료: 시작/최종 자산, 자산 증감, 실현손익, 운송비, 최고 수익 상품, 최고/최악 판매, 자주 간 항로, 자산 변화 차트

상단의 **플레이 기록 JSON** 버튼으로 진행 중인 게임도 다운로드할 수 있습니다. 종료 화면의 **전체 플레이 기록 JSON 내보내기** 버튼도 같은 데이터를 저장합니다. 파일에는 원래 행동 기록, 재현 가능한 플레이 분석 결과, 시장 정보 탭 조회 기록(`intelViews`)이 포함되어 추후 플레이테스트 비교에 사용할 수 있습니다. 조회 기록은 브라우저 로컬에 별도 저장되고, 새 게임이나 저장 삭제 시 초기화됩니다.

**주의:** 실현손익은 매입원가 대비 판매 손익으로, 운송비·업그레이드는 별도입니다. 자산에는 현재 도시 시세로 평가한 미판매 화물도 포함됩니다. 자산 차트에는 실제로 관측한 날짜만 표시하며 관측되지 않은 날짜의 자산을 만들어 내지 않습니다.

저장 버전은 의도적으로 `0.4.0`을 유지합니다. 0.5에서는 기존 게임 규칙이나 저장 행동 형식을 변경하지 않았기 때문에 **0.4 저장 데이터 그대로 이어하기**가 가능합니다.

## 0.4 경제 다양성

### 도시 생산 / 소비

도시별 가격 배율뿐 아니라 생산과 소비 성향이 실제 시장 재고·수요에 반영됩니다.

예시:

- 서울: 인삼·종이 생산 강점, 향신료 소비 강점
- 부산: 수산물 생산 강점
- 후쿠오카: 차·목재 생산, 인삼 소비
- 오사카: 철·도자기·구리 생산, 인삼 소비
- 상하이: 차·비단·면직물 생산, 목재 소비

생산 특성이 높은 상품은 평시 재고 목표가 크고 부족해졌을 때 회복도 빠릅니다. 소비 특성이 높은 상품은 평시 수요가 높고 수요가 시장 특성 쪽으로 돌아가는 힘도 강합니다. 0.4 밸런스 조정에서는 가격 배율과 생산/소비 계수가 같은 방향으로 과도하게 중복 증폭되지 않도록 생산·소비 정체성의 목표치 영향은 약 55%로 완화했습니다.

### 상품 특성

| 특성 | 효과 |
|---|---|
| 안정형 | 상대적으로 낮은 가격 변동과 이벤트 민감도 |
| 변동형 / 고변동 | 이벤트에 더 크게 반응 |
| 중량품 | 상품 1개당 화물칸 2칸 사용 |
| 신선품 | 이동으로 날짜가 지나면 신선도가 하락하고 실제 판매 가치도 감소 |

현재 신선품은 수산물이며, 신선도는 하루마다 약 7%씩 감소하되 최소 가치가 보장됩니다.

### 시장 이벤트

0.3의 단순 수요/공급 이벤트를 다음처럼 확장했습니다.

- 축제: 특정 상품 수요 급증
- 유행: 일정 기간 소비 증가
- 증산: 재고 증가와 공급 확대
- 공급 차질: 재고 감소와 공급 목표 하락

상품마다 이벤트 민감도가 달라 같은 사건도 가격 압력이 다르게 나타납니다.

### 항로 이벤트

항로도 항상 같은 비용과 시간이 보장되지 않습니다.

- 항로 혼잡: 운송비 +25%, 이동 +1일
- 순풍: 운송비 -12%, 이동 시간 최대 1일 단축

이 때문에 가장 큰 가격 차이가 항상 최고의 거래가 되지 않습니다.

## 저장 / 이어하기

브라우저 `localStorage`에 단일 저장 슬롯을 사용합니다.

- 매입 / 판매 / 이동 / 화물칸 확장 / 정보망 확장 후 자동저장
- 상단 `저장` 버튼으로 수동 저장 가능
- 새로고침하거나 다시 접속하면 저장 상태를 자동으로 복원
- `저장 삭제`로 로컬 저장 슬롯 삭제
- `새 게임`은 기존 저장을 덮어쓰기 전에 확인

저장 데이터는 현재 상태를 단순 복사하는 대신 **초기 난수 시드 + 성공한 플레이 행동 기록**을 저장합니다. 불러올 때 동일한 행동을 재생하므로 현재 시장뿐 아니라 이후 발생할 경제 변동과 이벤트의 난수 흐름도 이어집니다.

저장 형식은 버전 검사를 하며, 0.5는 기존 `0.4.0` 저장 데이터와 호환됩니다.

## 0.4 인삼 밸런스 조정

초기 봇 시뮬레이션에서 인삼이 대부분의 seed에서 최고 수익 상품이 되어 지역 정체성은 유지하되 가격 극단을 완화했습니다.

- 서울 인삼 가격 배율: `0.68 → 0.80`
- 서울 인삼 생산 계수: `1.40 → 1.25`
- 부산 인삼 가격 배율: `0.88 → 0.94`
- 후쿠오카 인삼 가격 배율: `1.34 → 1.22`
- 후쿠오카 인삼 소비 계수: `1.38 → 1.22`
- 오사카 인삼 가격 배율: `1.38 → 1.22`
- 오사카 인삼 소비 계수: `1.42 → 1.28`
- 상하이 인삼 가격 배율: `1.27 → 1.18`

서울은 여전히 인삼 생산지이고 일본 도시는 여전히 인삼 소비가 강하지만, 인삼 하나가 모든 다른 상품의 기회비용을 압도하지 않게 하는 것이 목적입니다.

### 비단 추가 조정

인삼 조정 후 상하이→후쿠오카 비단이 새 고정 정답 후보로 올라와 다음 값도 완화했습니다.

- 상하이 비단 가격 배율: `0.69 → 0.78`
- 상하이 비단 생산 계수: `1.45 → 1.30`
- 후쿠오카 비단 가격 배율: `1.16 → 1.10`

상하이는 여전히 비단 공급지이지만 한 상품/한 항로가 다른 선택을 압도하지 않도록 조정했습니다.


## 봇 시뮬레이션

UI 없이 실제 `Game` 코어를 직접 실행하는 headless 시뮬레이터입니다. 봇에게는 플레이어가 실제로 볼 수 있는 현재 도시 정보와 `remoteIntel()` 기반 원격 정보만 제공됩니다. GreedyBot의 이동은 실제 상품을 싣고 가는 `trade`와 정보 갱신을 위한 `explore/reposition`으로 구분하며, 고정 항로 밸런스 경고는 `trade` 이동만 집계합니다.

기본 실행은 RandomBot과 GreedyBot을 각각 100판씩 실행합니다.

```bash
npm.cmd run simulate
```

빠른 확인:

```bash
npm.cmd run simulate:quick
```

GreedyBot 1,000판 밸런스 실행:

```powershell
npm.cmd run simulate:balance
```

동일한 실행을 옵션으로 직접 지정할 수도 있습니다.

```powershell
npm.cmd run simulate -- --runs 1000 --bot greedy
```

상세 결과를 JSON 파일로 저장:

```bash
npm.cmd run simulate -- --runs 1000 --bot all --output simulation/report.json
```

지원 옵션:

- `--runs N`: 봇당 실행 횟수
- `--bot random|greedy|all`: 실행할 봇
- `--seed PREFIX`: 재현 가능한 시드 prefix
- `--output FILE`: 상세 JSON 리포트 저장
- `--quiet`: 콘솔 요약 숨김

리포트에는 평균/중앙 최종 자산, P10/P90, 실현손익, 운송비, 상품별 수익, seed별 최고 수익 상품 빈도, 단방향 항로 이용률, 왕복 항로 이용률, 완주율이 포함됩니다. 특정 상품의 양의 실현손익 비중이 35% 이상, 한 상품이 seed의 50% 이상에서 최고 수익, 단방향 항로가 30% 이상, 왕복 항로가 35% 이상이면 밸런스 경고를 표시합니다.

별도 npm 의존성 설치는 필요하지 않습니다.

GitHub Actions도 Windows GitHub-hosted runner를 기본 검증 환경으로 사용합니다. PR에서는 GreedyBot 100판 밸런스 샘플도 실행합니다. Linux 검증은 Actions의 수동 실행에서 `runner: linux`, 로컬 Windows self-hosted 검증은 `runner: local`로 선택할 수 있습니다.
